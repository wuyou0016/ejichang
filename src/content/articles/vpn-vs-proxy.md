**先给结论**：VPN 和代理都是“让流量绕到另一台服务器再出去”，区别主要在**工作的层级和覆盖范围**。VPN 一般建立一条虚拟的网络通道，覆盖整台设备的流量；代理一般针对某个软件或某种协议（HTTP、SOCKS 等）转发流量。现实中很多产品界限并不严格，名称也常常混用，所以看名字不如看它实际怎么工作。

## 核心区别对比

| 对比项 | VPN | 代理 |
| --- | --- | --- |
| 工作层级 | 多在网络层或系统层，创建虚拟网卡或隧道 | 多在应用层，软件把请求发给代理服务器 |
| 覆盖范围 | 通常整台设备的流量 | 只覆盖设置了代理的软件 |
| 加密 | 通道一般带加密，具体取决于协议 | 取决于代理协议，有的不加密，有的加密 |
| 设置方式 | 安装客户端或系统配置，一键开关 | 在软件或系统里填地址和端口，或使用客户端 |
| 灵活性 | 通常按整个通道处理，规则较少 | 可以按域名、应用做规则分流 |
| 常见协议 | OpenVPN、WireGuard、IPsec 等 | HTTP、SOCKS5、Shadowsocks 等 |

需要说明的是，这是通用的技术对比，不同产品可能同时具备两种形态。

## 更直观地理解

- **代理**像是“让一个中间人替你去买东西”，你告诉中间人要买什么，它去办，再把东西转给你。哪些东西交给中间人，由你决定；
- **VPN** 像是“在你和远端之间挖了一条专用通道”，从你的设备出去的流量默认都走这条通道。

## 加密和安全，要分开看

1. **加密不等于匿名**：加密保护的是你到服务器之间这一段，服务器一端仍然可以看到你访问了什么，除非你使用的目标本身也加密；
2. **代理不一定加密**：普通 HTTP 代理只是转发，不提供加密；
3. **VPN 也要看服务方的可信度**：所有流量经过它，选择不可信的服务风险更大，见 [免费 VPN 的风险](/knowledge/free-vpn-risk/)；
4. **DNS 泄露**：无论用哪一种，DNS 配置不当都可能暴露访问记录，见 [DNS 泄露说明](/knowledge/dns-leak-note/)。

## 速度和延迟的差别

- 速度主要取决于线路、节点负载、协议效率，而不是名称是 VPN 还是代理；
- 加密和封装会带来一定开销，但在现代设备上通常不是主要瓶颈；
- 需要精细分流的代理，可以让不需要绕路的流量直连，整体体验更好。

## 按需求选择

| 你的需求 | 更合适的方式 |
| --- | --- |
| 整台设备的流量都想走加密通道 | VPN 或带 TUN 的代理客户端 |
| 只想让浏览器或某个软件走代理 | 应用层代理、浏览器插件 |
| 需要规则分流，国内直连、海外走代理 | 支持规则的代理客户端 |
| 公共 Wi-Fi 下保护基本传输 | 可信的 VPN 服务 |
| 让不支持代理设置的设备也能用 | VPN 或路由器层方案 |

具体产品选择，可以先看 [VPN 与机场怎么选](/knowledge/vpn-or-airport/)。

## 协议只是实现方式

无论 VPN 还是代理，具体表现还取决于协议：

- 协议决定加密方式、握手速度、抗干扰能力；
- 不同协议对客户端的支持情况不同；
- 详细介绍见 [VPN 协议说明](/knowledge/vpn-protocols-explained/) 与 [协议对比](/knowledge/protocols-compared/)。

## 用一次网页访问看两者的差别

以访问一个网站为例，可以更具体地看到两者在流程上的差别。

**通过应用层代理访问：**

1. 浏览器（或其他软件）被设置为把请求交给代理服务器；
2. 软件在发起请求时，把目标地址告诉代理，请求由代理服务器代为发出；
3. 代理服务器拿到响应后，再转交给软件；
4. 没有设置代理的软件，仍然直接访问网络，不受影响。

**通过 VPN 访问：**

1. 客户端在系统里创建一个虚拟网卡，并修改路由，让流量默认进入这个虚拟网卡；
2. 数据被加密并封装，发往 VPN 服务器；
3. VPN 服务器解封装后，把请求发往目标网站；
4. 系统中的软件并不知道自己走了 VPN，按平常方式联网即可。

这就是为什么 VPN 常常显得“更省心”，而代理更“可控”。两种方式没有绝对的好坏，只是控制的粒度不同。

## 现实中的产品经常是混合形态

- 很多代理客户端提供“虚拟网卡模式”，效果接近 VPN；
- 一些 VPN 应用在内部使用的是代理类协议，只是对用户表现为“一键连接”；
- 路由器层面既可以运行 VPN，也可以运行代理；
- 有的服务同时提供两种接入方式，由用户选择。

所以遇到产品时，不必纠结它叫什么，而要看它是否满足你的需求：覆盖范围、加密方式、是否支持规则分流、客户端是否易用、是否可信。

## 选择前的问题清单

1. 我要保护或转发的是整台设备，还是某几个软件？
2. 我是否需要国内外流量分开处理？
3. 我的设备有没有系统限制，是否只能用某一种方式？
4. 服务方的信息是否公开透明？
5. 出现问题时，我有能力排查，还是更需要简单的一键式体验？

回答完这些问题，选择往往就清楚了。

## 常见误区

- **“VPN 一定比代理安全”**：安全取决于协议、服务方和你的使用习惯，不是名称；
- **“代理一定比 VPN 快”**：速度取决于线路，不取决于类型；
- **“开了就完全匿名”**：转发流量不意味着匿名，登录账号后网站依然能识别你；
- **“名称叫 VPN 就是标准 VPN”**：很多产品只是借用这个名称，最好看它的技术说明。

## 怎么自己验证

1. 打开客户端，查看它是系统级通道还是应用代理；
2. 在系统的网络设置里，看是否新增了虚拟网卡或代理设置；
3. 分别打开浏览器和命令行，看流量是否都经过它；
4. 关闭后，确认一切恢复；
5. 需要更多背景知识时，再看 [梯子、VPN 与机场的关系](/knowledge/ladder-vpn-airport-relationship/)。
