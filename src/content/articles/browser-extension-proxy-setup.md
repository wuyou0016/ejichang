**先给结论**：浏览器代理插件适合"只想让浏览器访问个别网站，其他软件不受影响"的场景，配置比系统代理或 TUN 模式简单，但它**不能直接识别订阅链接**，必须先有一个本地运行的客户端把节点转换成一个本地端口，插件只是把浏览器流量指向这个端口。

## 插件和客户端是什么关系

机场订阅里的节点，协议通常是 Shadowsocks、V2Ray、Trojan 等，浏览器插件本身并不认识这些协议，它只会把流量转发到你指定的 HTTP 或 SOCKS5 地址。所以完整的链路是：

1. 本地客户端（如 Clash）导入订阅，连接到某个节点；
2. 客户端在本机开出一个 HTTP 或 SOCKS5 监听端口；
3. 浏览器插件把浏览器的网络请求指向这个本地端口；
4. 客户端再把请求转发给远端节点。

也就是说，插件只负责"浏览器流量往哪发"，真正的订阅导入和节点连接，仍然要靠客户端完成，这一步可以参考 [机场订阅链接导入教程](/tutorials/how-to-import-subscription/) 或 [Clash 客户端配置教程](/tutorials/clash-desktop-setup/)。

## 适合和不适合的场景

| 情况 | 是否适合用浏览器插件 |
| --- | --- |
| 只在浏览器里访问少数几个网站 | 适合 |
| 临时测试节点是否可用 | 适合 |
| 手机 App、客户端软件也需要走代理 | 不适合，插件只管浏览器 |
| 需要联机游戏、UDP 转发 | 不适合，插件不处理这类流量 |
| 想要所有软件统一走同一条线路 | 不适合，更适合系统代理或 TUN 模式 |

系统代理、TUN 模式和浏览器插件三种接入方式的对比，可以看 [电脑梯子怎么选](/knowledge/computer-ladder-guide/)，那篇文章会帮你判断自己更适合哪一种。

## 配置前要准备的信息

打开客户端的设置或"端口"页面，找到下面两项：

- **本地监听地址和端口**：通常是 `127.0.0.1` 加一个端口号，HTTP 和 SOCKS5 的端口可能不同；
- **代理是否已经连接到某个节点**：插件只负责转发，客户端没连上节点的话，插件配置再对也打不开网页。

## 配置步骤（通用流程）

1. 确认客户端已经正常连接节点，并记下它的本地 HTTP 或 SOCKS5 端口；
2. 在浏览器的扩展商店安装一个代理管理类插件（选择来源正规、评价正常的扩展，不要装来路不明的插件）；
3. 在插件里新建一个代理配置：协议选 HTTP 或 SOCKS5，地址填 `127.0.0.1`，端口填第 1 步记下的端口；
4. 根据需要选择"全部流量走这个代理"或者"按规则/PAC 自动判断"，日常使用更推荐按规则，境内网站直连、境外网站走代理；
5. 保存配置并切换到它，打开一个网页测试是否能正常访问。

## 用规则还是全局，怎么选

多数代理管理插件会提供两种工作方式：

| 方式 | 做法 | 适合情况 |
| --- | --- | --- |
| 规则 / PAC 自动切换 | 插件按域名列表判断，命中的网站走代理，其余直连 | 日常使用，境内网站不受影响 |
| 全局 | 浏览器所有请求都走这个代理 | 临时排查，确认代理本身是否可用 |

日常建议用规则模式，只让需要的网站走代理，这样打开国内网站时速度不受影响，也能减少不必要的流量消耗。排查问题怀疑是规则没命中时，可以临时切到全局，确认是规则的问题还是代理本身的问题，确认完再切回规则模式。

## 常见问题排查

| 现象 | 可能原因 |
| --- | --- |
| 插件显示已启用，但网页打不开 | 客户端没有连接到可用节点，或端口号填错 |
| 部分网站能打开，部分打不开 | 规则/PAC 判断把该网站划到了直连，需要调整规则 |
| 刚才还能用，突然不行了 | 客户端可能断开了连接，或者切换、重启后本地端口变化 |
| 网页能打开但很慢 | 插件只代理浏览器请求，具体速度仍取决于节点本身，和插件配置无关 |

如果确认端口和节点都没问题，但依然无法访问，可以按 [机场连不上、网页打不开怎么排查](/troubleshooting/connection-failed-troubleshooting/) 里的顺序逐层排查。

## 完整自查顺序

遇到问题时，按这个顺序排查，比逐项猜测更快：

1. 客户端是否在运行，是否已经连接到某个节点；
2. 客户端里的本地端口号，和插件里填写的是否一致；
3. 插件当前是否处于"启用"状态，而不是临时关闭了；
4. 换一个节点后，是否需要重新确认端口号（部分客户端重启或切换协议后端口会变化）；
5. 排除插件本身的问题：临时禁用插件，直接在客户端里切到全局模式测试，能打开说明问题在插件配置或规则上。

## 需要留意的几点

- 插件只处理浏览器发出的请求，浏览器之外的软件（邮件客户端、下载工具等）不会受影响，也不会被保护；
- 部分系统或应用会单独发起 DNS 查询，不经过浏览器代理，存在和代理不一致的可能，相关背景可以看 [DNS 泄露是什么](/knowledge/dns-leak-note/)；
- 不要把订阅链接直接填进浏览器插件——插件不需要、也无法使用订阅链接，只需要本地端口号；
- 只从浏览器官方扩展商店安装代理插件，插件本身拥有读取和修改网页流量的权限，来源不明的插件存在安全风险。

## 什么时候该换成客户端的系统代理或 TUN 模式

浏览器插件的覆盖范围有限，出现下面任一情况，说明已经不适合继续只用插件：

- 发现某个桌面软件（不是浏览器）也需要走代理才能正常使用；
- 频繁需要在"只代理浏览器"和"代理全部流量"之间切换，操作变得麻烦；
- 需要用到游戏、视频通话等依赖 UDP 的场景。

这种情况下，直接在客户端里开启系统代理或 TUN 模式会更省心，具体对比可以回到 [电脑梯子怎么选](/knowledge/computer-ladder-guide/) 里查看。

机场是否提供可以直接使用的本地端口说明、客户端是否支持这种用法，具体以服务商文档为准，机场导航收录的资料可以作为起点，例如[无忧链接](/airports/wuyou-lianjie/)的客户端说明。
