**先给结论**：路由器方案的价值是**让不能装客户端的设备（电视、游戏机、智能家居）也能使用**，并且不占用每台设备的设备数额度。代价是：对路由器性能要求较高、配置和排错更复杂、一旦出问题会影响全家。多数只用手机和电脑的人，直接在设备上使用客户端更简单。

## 路由器方案在做什么

正常情况下，设备通过路由器连接互联网。启用路由器层的 VPN 或代理后，路由器会：

1. 接收局域网设备发来的流量；
2. 按规则判断，哪些流量走代理或 VPN 通道，哪些直接放行；
3. 需要转发的部分，加密封装后发往远端服务器；
4. 返回的数据再由路由器交还给对应设备。

也就是说，转发这件事从“每台设备自己做”变成了“路由器统一做”。

## 优点与缺点对比

| 对比项 | 路由器层 | 设备层（各自装客户端） |
| --- | --- | --- |
| 覆盖设备 | 局域网内的设备都可覆盖 | 只覆盖已安装的设备 |
| 适用于不能装客户端的设备 | 是 | 否 |
| 设备数量限制 | 对服务方来说通常是一台设备，具体以服务方规则为准 | 每台设备各自计算 |
| 性能要求 | 依赖路由器 CPU 和内存，加密开销集中在路由器 | 分散在各设备 |
| 灵活性 | 分流规则需要在路由器上配置，修改不方便 | 每台设备可以单独调整 |
| 出问题的影响 | 全家受影响 | 只影响单台设备 |
| 出门在外 | 离开家就不再生效 | 设备走到哪里都可用 |

## 是否适合你的判断

更适合路由器方案的情形：

- 电视、盒子、游戏机等设备无法安装客户端，见 [智能设备使用说明](/knowledge/airport-multi-device/)；
- 家里设备很多，且使用需求一致；
- 你愿意花时间学习和维护；
- 路由器硬件性能足够。

更适合设备层方案的情形：

- 只在手机和电脑上使用；
- 需要按设备、按软件灵活切换；
- 更换服务、更新订阅比较频繁；
- 不想因为配置问题影响全家上网。

## 需要留意的问题

1. **性能瓶颈**：加密和转发会占用路由器 CPU，硬件较弱时，速度会明显下降，选择协议时要考虑运算成本，可参考 [协议对比](/knowledge/protocols-compared/)；
2. **协议支持**：路由器系统对协议和功能的支持因固件而异，先确认想用的协议是否被支持；
3. **DNS 与分流**：家里的设备都会受影响，DNS 配置不当会出现解析异常或泄露，见 [DNS 泄露说明](/knowledge/dns-leak-note/)；
4. **国内外分流**：所有流量一律走代理会让国内应用变慢，需要设置规则，让国内流量直连；
5. **订阅更新**：订阅节点会变化，需要确认路由器是否能自动更新；
6. **备用方案**：路由器一旦配置出错，全家断网，最好保留恢复出厂设置的方法，以及一条不经过代理的备用网络；
7. **服务方规则**：是否允许在路由器上使用，设备数如何计算，以服务方的说明为准；
8. **系统改动风险**：对路由器系统进行改动有变砖或影响保修的可能，请先阅读设备官方说明并自行承担风险。

## 常见的实现思路（不涉及具体品牌）

- **路由器自带 VPN 客户端功能**：适合使用标准 VPN 协议的服务，设置相对简单，见 [VPN 协议说明](/knowledge/vpn-protocols-explained/)；
- **在路由器上运行代理客户端**：可以做规则分流，灵活但对硬件有要求；
- **使用独立的小型主机作为旁路网关**：让需要的设备把网关指向它，与主路由分工，影响范围较小；
- **只对特定设备启用**：在路由器上按设备或地址段设置策略，减少对全家的影响。

## 上手前的检查清单

1. 确认你的路由器硬件规格和能否运行所需功能；
2. 确认服务方允许在路由器上使用；
3. 先在电脑上验证服务可用，再上路由器；
4. 先只对一台设备测试，稳定后再扩展；
5. 备份路由器当前配置；
6. 记录改动步骤，便于回退；
7. 准备一条不经过代理的应急网络，如手机热点。

## 分流思路：让谁走代理

路由器方案里最容易出问题的是分流。可以按下面几个层次来设计：

| 分流依据 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 按设备 | 只有指定的设备（如电视盒子）走代理 | 影响范围小，容易理解 | 设备地址变化时需要更新 |
| 按目标域名或地址 | 命中规则的流量走代理，其余直连 | 国内外流量自动区分 | 规则需要维护，可能漏掉某些域名 |
| 全部转发 | 局域网内所有流量都走代理 | 配置简单 | 国内应用变慢，流量消耗大，一旦出错全家受影响 |
| 按时间或场景 | 需要时才开启 | 灵活 | 依赖人工操作 |

比较稳妥的做法，是先从“只对少数设备启用”开始，稳定后再逐步扩大范围。

## 旁路网关与主路由方案的区别

- **主路由方案**：把代理直接部署在主路由器上，所有设备天然经过它。好处是结构简单，缺点是一旦配置错误，全家断网；
- **旁路方案**：另有一台小主机作为网关，只有把网关指向它的设备才会经过代理。好处是可以按设备灵活切换，出问题时只需把网关改回来；缺点是需要多一台设备和额外的网络知识。

无论哪种，都建议把家里的重要设备（比如需要稳定联网的办公电脑）放在可以随时切回直连的位置，以免误伤。

## 协议与硬件的匹配

不同协议的运算开销不同，在性能有限的路由器上，选择合适的协议很关键：

- 加密强度越高、握手越复杂，对 CPU 的占用越大；
- 部分设备支持硬件加速，但只对特定的加密算法有效；
- 多设备同时使用时，连接数多，内存占用也会增加；
- 具体表现因设备和固件而异，需要自己测试，本站没有对任何设备做实测。

协议的基本特点可以参考 [协议对比](/knowledge/protocols-compared/)，然后结合你的硬件规格来选。

## 出问题时的回退方案

1. 保留恢复出厂设置的方法，并提前了解如何进入路由器的管理页面；
2. 配置前导出当前的设置备份；
3. 一次只改一项，改完就测，出问题时容易定位；
4. 家里保留一个不经过代理的备用网络，比如手机热点；
5. 告知家人配置改动的时间，避免在重要场合（如视频会议）前后修改。

## 常见误区

- **“路由器上配一次，全家永远省心”**：订阅更新、节点变化仍需维护；
- **“路由器性能越好越无所谓”**：即便性能强，配置错误也会带来问题；
- **“所有设备都应该走代理”**：国内应用和内网设备通常不需要；
- **“路由器方案更安全”**：安全性取决于服务方和配置，而不是位置。
